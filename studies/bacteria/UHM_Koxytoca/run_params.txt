# Extra nextflow params for this study, applied by bin/run_study.sh before any
# args passed on the command line (so a command-line arg can still override one
# of these). One flag/value per line; '#' starts a comment; blank lines ignored.
#
# All paths below are absolute: nf_NovInvenio's file(params.X) calls resolve a
# relative path against the nextflow process's own launch cwd (NII's repo root),
# not against the NovInvenio checkout the db/ files actually live under.

# diamond over phmmer: 34 bacterial proteomes, speed matters more here than
# phmmer's sensitivity edge.
--run_tool diamond

# pairwise clustering (not mmseqs/novelty_discovery) -- also the only cluster_tool
# path that runs the generic VALIDATE (TBLASTN vs outgroup DNA) workflow, which
# it runs against the outgroup (Group=OUT) rows' DNA specifically. Since this
# study's 2026-09-11 migration onto the unified bin/build_study_config.py, DNA
# is populated in config.csv/data_dir/dna for both IN (Genome_Source=local_genome)
# and OUT (Genome_Source=ncbi) rows -- VALIDATE's outgroup-only behavior comes
# from nf_NovInvenio filtering on the Group column, not from DNA being absent
# for the ingroup.
#
# SCOPE CHANGE from the same 2026-09-11 migration: main.nf's LOSS_VALIDATE
# (the loss-direction counterpart of VALIDATE, run whenever cluster_tool !=
# 'novelty_discovery' -- true here, ~main.nf:344-345) is fed `ingroup_dna_ch`
# (~main.nf:121), i.e. the Group=IN rows' DNA. Before this migration, the old
# per-study script never populated ingroup DNA at all, so ingroup_dna_ch was
# empty and LOSS_VALIDATE's TBLASTN step had nothing to run against for this
# study. Now that the 18 ingroup MAG genomes have real DNA
# (Genome_Source=local_genome) for the first time, the next pipeline run will,
# for the first time, execute LOSS_VALIDATE's TBLASTN against all 18 ingroup
# MAG genomes -- a real increase in scientific scope and compute cost versus
# prior runs of this study, not just a file-naming/config change.
--cluster_tool pairwise

# Pfam-A + SwissProt-diamond annotation: unlike the UniProt-sourced fungal
# pezizo_set1 study, these proteomes (NCBI RefSeq outgroup + prodigal-called UHM
# MAG ingroup) carry no precomputed Pfam/GO/InterPro cross-references of their
# own, so a fresh hmmscan/diamond-vs-swissprot pass is the only annotation source
# here (not redundant, unlike pezizo_set1's reasoning for omitting these).
--pfam_hmm /bigdata/stajichlab/jstajich/projects/NovInvenio/db/pfam/38.2/Pfam-A.hmm
--swissprot_dmnd /bigdata/stajichlab/jstajich/projects/NovInvenio/db/uniprot/uniprot_sprot.fasta.dmnd

# Kpn78578 (K. pneumoniae MGH 78578) model organism gene-name/product lookup for
# the ingroup MAGs -- see modelorgs.yaml + config_support/MODELORG_KPN78578_PROVENANCE.md.
--modelorgs_config /bigdata/stajichlab/jstajich/projects/NovInvenio_Investigations/studies/bacteria/UHM_Koxytoca/modelorgs.yaml
