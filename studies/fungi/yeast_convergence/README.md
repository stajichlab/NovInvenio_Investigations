# yeast_convergence: independent yeast origins, one pairwise run each

Status: **draft, nothing run yet.** No data pulled, so no `DATA_MANIFEST.yaml`
in any contrast (it is written by `bin/build_study_config.py` when the pull runs).

## Question

Nagy et al. 2014 (*Nat Commun* 5:4471, doi:10.1038/ncomms5471) proposed that yeast
growth evolved repeatedly by re-deploying an old cell-separation toolkit through
regulatory change, with parallel Zn-cluster (Zn2Cys6) transcription-factor
expansion and convergent loss of hyphal and plant-cell-wall genes. They mapped
gains and losses once, over 59 genomes, with each yeast clade compared against
the whole tree.

This folder re-tests that claim as a **series of independent pairwise runs**:
each yeast origin against its own closest filamentous sister lineage, plus two
kinds of control. Convergence is then read across runs, not inside any one.
This differs from `studies/fungi/yeast_filamentous/`, which pools four
Saccharomycotina/Taphrinomycotina yeasts against one Pezizomycotina panel.

## The contrasts

**`COMPARISONS.md`** lists all 16 runs, with every species, its growth-form
state and whether its accession is filled. It is generated from the batch
YAMLs (`bin/yc_batches.py table`), and a test fails if it is out of date.
**`PLAN.md`** has the hypotheses, the steps with their checks, how results will
be read, and the open decisions.

In short: 9 origin runs, 2 reversal runs, 5 control runs.

- **Origins** test what each yeast lineage gained (novelty) and lost relative to
  a filamentous sister. "Dominance" origins have a dimorphic outgroup, so they ask
  what makes the yeast phase *dominant*, not what gives the capacity. The
  Mucorales run asks about capacity only.
- **Reversals** are filamentous lineages nested inside yeast clades. If yeast
  form evolves by regulation of a retained toolkit, they should not regain the
  hyphal genes their yeast relatives lost.
- **Pseudo-origins** are filamentous lineages with large ecological gene loss
  but no growth-form change. A term that recurs in yeast origins *and* here is
  streamlining, not yeast biology. The two **deep** controls (arbuscular
  mycorrhizal fungi, a subphylum-level split; lichen Lecanoromycetes, a
  class-level split) match the depth of most yeast origins. The other three
  controls are family- or order-level splits, which give shorter lists for
  reasons of depth alone.

Each run records `split_rank`, the rank at which its IN and OUT groups split
(genus to phylum). `convergence_compare.py` reports for every recurrent term how
many controls at class depth or deeper (`n_pseudo_deep_sig`) also called it.
The two deep controls share no species with any other run.

Species reasons, caveats and confounds for each run are written next to it in
the batch YAMLs.

## Growth-form coding

Each species carries `growth_form` (the `cell_morphology` vocabulary:
yeast / filamentous / dimorphic) and, if dimorphic, `dominant_phase`
(yeast / hyphal). Together these give the three states the 2014 study
collapsed into "can grow as yeast": filamentous, dimorphic with hyphal
dominance, and yeast-dominant. `yc_batches.py check` enforces that every origin
has a yeast-dominant ingroup (a yeast-capable one for the `dimorphic_*` capacity
contrast) and a filamentous or hypha-dominant outgroup, and that controls are
filamentous on both sides.

These codings are not in `config_support/traits/` yet and need a source per
row before they go there. `check` lists disagreements with the curated
`traits.csv`. Two are left, both genus-level FUNGuild calls: *Yarrowia
lipolytica* (traits.csv: yeast; here dimorphic) and *Eremothecium cymbalariae*
(traits.csv: yeast, from the genus call that would also make *E. gossypii* a
yeast; here filamentous). FUNGuild codes the whole of Herpotrichiellaceae as
dimorphic, which is why `yc_chaetothyriales` is a dominance contrast.

## Running it

On the cluster, from the NII checkout:

```bash
F=studies/fungi/yeast_convergence
# 0. Validate; with the master pool, also list species NovInvenio's pool lacks
python3 $F/bin/yc_batches.py check --master-pool /path/to/NovInvenio/config_support/master_pool.csv
# 1. Fill blank source columns (UniProt first, NCBI fallback) for each contrast
for d in $F/yc_*/; do pixi run python bin/ni resolve --study-dir "$d"; done
#    Fix any row resolve leaves blank by hand. render will not overwrite these files.
# 2. Submit the pipeline runs (skips any contrast still unresolved)
DRY_RUN=1 $F/bin/run_all.sh && $F/bin/run_all.sh
# 3. After the runs and the Pfam annotation jobs finish
sbatch $F/bin/run_enrichment_all.sh
# 4. Cross-contrast comparison -> $F/analysis/convergence/
python3 $F/bin/convergence_compare.py
```

`bin/run_study.sh` accepts the nested path (`fungi/yeast_convergence/<id>`) and
names the pipeline project and `results/<id>` after the contrast id. Report
sync and the gallery also accept it: `bin/study_pages.py` takes a nested
`<domain>/<folder>/<contrast>` argument, `bin/sync_reports.sh` takes DOMAIN from
the first path component, and `bin/generate_docs.py` lists contrasts inside a
grouping folder. Each contrast publishes as its own study,
`docs/fungi/<id>/pairwise-diamond/`.

### Accessions

The 16 contrasts use 106 distinct species: 31 are prefilled, 75 need
`bin/ni resolve`. Several are in the lab's local genome lists
(`config_support/1KFG_samples.csv`: *S. octosporus*, *Protomyces inouyei*,
*Rhodotorula graminis*, *Laccaria amethystina*, both *Amanita*, *B. hordei*,
*Rhizophagus irregularis*, *Umbelopsis ramanniana*, *Cladonia grayi*,
*Xanthoria parietina*, and all four lichen-run outgroups;
`Chaetothyriales_samples.csv`: the added *Exophiala*), so if resolve finds no
public proteome, point those rows at the local FASTA (`Protein_Source=local_faa`). `render` prefills a row only when another tracked `species.csv` in this repo
already uses exactly one UniProt proteome for that species (so the same
proteome is reused across studies). Everything else is blank for `bin/ni resolve`.
UniProt's API was not reachable from where these files were drafted, so
**whether every listed species has a usable proteome is unverified**. Expect a
few substitutions (likely candidates: *Mucor racemosus*, *M. indicus*,
*Hortaea thailandica*, *Eremothecium sinecaudum*, *Golovinomyces orontii*,
*Kwoniella mangroviensis*, *Dothistroma septosporum*, *Geosiphon pyriformis*,
*Lobosporangium transversale*, *Umbilicaria pustulata*, *Evernia prunastri*).
For the lichen run, use mycobiont-only proteomes; a metagenome-derived one
would add algal and bacterial "novelties".
Change the YAML, then `render --force` for that contrast only after saving any
resolve output you want to keep.

## What the comparison does and does not test

`convergence_compare.py` asks, per vocabulary and direction, whether a term is
significant in more origin contrasts than independent draws of each
contrast's own hit rate would give (Poisson-binomial, BH-corrected). Recurrent
terms are then split into `yeast_convergent` (not significant in any
pseudo-origin) and `streamlining_generic`. It also writes the reversal overlap,
the focus-family grid and `annotation_coverage.tsv`.

- **Primary call: Pfam and Pfam clan, over every contrast.** Every proteome
  has Pfam (from UniProt, or from the HMMER step for NCBI/JGI proteomes).
- **Secondary: GO and InterPro, only over contrasts whose proteomes are all
  UniProt.** NCBI/JGI proteomes get no GO or InterPro terms, so a mixed contrast
  would under-call them. `--include-mixed-annotation` turns this off.
- **Single-species ingroups contribute losses only** (`--min-in-novelty`,
  default 2), since a one-genome novelty list is mostly orphans and annotation
  artefacts. This affects `yc_rev_neolecta`.

It does **not** test family *expansion*. NovInvenio calls presence and absence
of orthogroups, and the 2014 Zn-cluster result is about copy-number growth
within a family that both sides have. That needs per-family copy numbers and a
birth–death model (for example CAFE5) on the same species sets, as a separate
step. In the existing pooled `yeast_filamentous` run, Zn_clus (PF00172) is not
enriched among yeast novelties (k = 1, fold 0.43) or losses (k = 59, fold
0.93). That is consistent with the expansion being within shared families, not
evidence against it.
